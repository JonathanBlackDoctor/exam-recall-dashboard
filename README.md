# 복기 기록

**시험별 기여를 한눈에.**

출석번호순 히트맵으로 시험별 복기 기여를 비교하고, 각 점수의 기본·초과·보충 구성을 확인하는 웹앱입니다. 네이비 타이포그래피와 코발트 블루, 여백이 넉넉한 카드로 로그인부터 히트맵·상세·점수 안내까지 같은 디자인을 사용합니다.

[대시보드 열기](https://jonathanblackdoctor.github.io/exam-recall-dashboard/) · [점수 기준](docs/scoring-guide.md) · [디자인 기준](docs/design-system.md)

## 화면과 사용법

1. 공유받은 비밀번호로 **기록 열기**를 누릅니다. 점수 기준은 기록을 열기 전에도 읽을 수 있습니다.
2. 기본 화면은 **본1 메이저**입니다. 본1 전체·예2 전체·전체 시험을 빠르게 선택하거나 **과목 선택**에서 원하는 조합을 적용합니다.
3. 이름·출석번호를 검색하고 **표시 척도**를 바꿔 비교합니다. 사람과 시험 헤더는 스크롤 중에도 고정됩니다.
4. 히트맵의 칸을 누르면 해당 사람·시험의 **기여 요약**이 열립니다. 히트맵으로 돌아오면 비교하던 스크롤 위치와 칸에 복귀합니다.
5. **점수 기준**의 두 페이지에서 배점·계산, 용어·판정을 확인합니다. 휴대전화에서는 표를 가로로 스크롤하고 안내 본문을 세로로 읽을 수 있습니다.

| 표시 척도 | 의미 |
|---|---|
| 총점 | 기본 점수 + 초과 복기 점수 + 보충 점수 |
| 본복기 문항 수 | 기본 배점 적용 문항 + 초과 본복기 문항 |
| 보충 문항 수 | 별도 문항의 보충·답만 제공 |
| 기본 점수 | 높은 배점의 최대 두 본복기 문항 |
| 초과 복기 점수 | 나머지 본복기 문항 수 × 0.3점 |
| 보충 점수 | 별도 보충·답만 제공 문항 수 × 0.1점 |

같은 척도의 같은 값은 모든 시험에서 같은 색입니다. **0은 응시했으나 기여 없음**, **—는 미응시 결측**으로 구분합니다. 점수는 소수점 한 자리, 문항 수는 정수로 표시하며, 색은 통과 여부를 뜻하지 않습니다.

2026-10-10 승인된 두 장의 점수 안내 스타일을 웹 전체에 적용했습니다. 계산 규칙과 데이터 어댑터는 유지하고 표시 색·배치·탐색을 개편했습니다.

## 개발 및 검증

Node 24 이상과 pnpm 11.25.0을 사용합니다.

```sh
pnpm install --frozen-lockfile
pnpm test
pnpm build
node scripts/audit-public.mjs
pnpm dev
```

테스트는 정수 점수·결측 검증, 과목 기본값과 순서, 문항 수, 색 대비, 암호화·잘못된 비밀번호·변조를 확인합니다. 화면 검증은 이름을 가상 표기로 바꾼 로컬 암호문을 사용합니다. `DASHBOARD_FIXTURE_DIR`로 개발 서버의 public 디렉터리를 지정할 수 있으며, 해당 자료는 Git 제외 경로에 둡니다.

주요 UI는 `src/main.tsx`, 두 페이지 안내는 `src/ScoringGuide.tsx`, 공통 모달은 `src/Dialog.tsx`, 색·반응형 배치는 `src/style.css`에서 관리합니다. 외부 폰트·아이콘·분석 서비스 요청 없이 동작합니다.

## 데이터 갱신

이 저장소에는 원문·실명 평문·비밀번호를 넣지 않습니다. 원본 분석 작업 폴더의 `web` 하위에서 `scripts/build-data.mjs`를 실행합니다. 변환기는 검증 보고서의 점수 파일·원본 해시, 응시명단 독립 검증, 완전한 사람×시험 조합과 정수 점수 구성을 확인합니다. 점수를 다시 계산하지 않으며 필요한 요약 필드만 가져옵니다.

공유 비밀번호를 명령 인수나 환경 변수에 기록하지 말고 표준입력으로 전달합니다. 기본 출력은 `public/data.enc.json`입니다. 갱신마다 새 salt와 IV로 암호화합니다. 로컬 감사 기록과 Windows 사용자 계정으로 보호한 DPAPI 자격정보는 Git 제외 경로 `.private/`에 둡니다. 로컬의 `비밀번호 확인.cmd`로 접속 비밀번호를 확인할 수 있습니다.

배포 전 `node scripts/build-data.mjs --audit`로 실제 이름이 빌드 결과에 포함되지 않았는지도 확인합니다. 데이터 변경 없이 재배포할 때에는 기존 암호문을 재사용할 수 있습니다.

## 배포와 접근

`main` 변경을 GitHub Actions가 검사·빌드한 뒤 GitHub Pages로 배포합니다. GitHub Pages 설정의 Source는 GitHub Actions입니다. 서버나 분석 서비스로 복호화 결과를 전송하지 않으며 비밀번호·복호화 결과를 브라우저 저장소에 보관하지 않습니다. 잠그기 또는 새로고침 시 다시 입력합니다.

AES-256-GCM, PBKDF2-SHA-256 600,000회를 사용합니다. 공개 암호문은 오프라인 추측이 가능하므로 짧은 숫자 비밀번호는 접근 보호가 약합니다. 공유 비밀번호 방식은 개인별 권한이나 접속 기록을 제공하지 않습니다. 원본·이미지·문항별 근거·누적 점수·평균·순위는 포함하지 않습니다.
